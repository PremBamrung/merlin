# Frontend v3 — Patterns & Conventions

> How the `web/` app is built and behaves. Companion to `FRONTEND_V3_PLAN.md`
> (stack/arch), `FRONTEND_V3_DESIGN_SYSTEM.md` (visual), `FRONTEND_V3_SCREENS.md`
> (screens). This is the doc that keeps every feature a **fully-wired vertical
> slice** instead of a placeholder.

## 1. Folder structure

```
web/src/
  routes/                 # one file per screen; thin — composes hooks + components
    today.tsx  library.tsx  reader.tsx  chat.tsx  inbox.tsx  insights.tsx
  components/
    ui/                   # shadcn primitives (owned, generated by CLI)
    layout/               # AppShell, Sidebar, Topbar, CommandPalette
    items/                # ItemCard, ItemGrid, TagInput, StatusDot
    ingest/               # AddSourceDialog, TaskRow, TaskPanel
    chat/                 # MessageList, CitationCard, FilterBar
    common/               # EmptyState, ErrorState, Skeletons, Markdown
  lib/
    api/
      client.ts           # fetch wrapper (base URL, errors, SSE helper)
      schema.d.ts         # GENERATED by openapi-typescript (do not edit)
      endpoints.ts        # typed functions: getItems(), getItem(), ingest()…
    queryKeys.ts          # central query-key factory
    format.ts             # ts_to_seconds, relDate, youtubeUrl, shortText…
    classify.ts           # omnibox URL-vs-question classifier
  hooks/                  # useItems, useItem, useIngest, useChatStream, useTaskProgress
  store/                  # zustand: ui.ts (palette, density, filters draft)
  styles/                 # tailwind entry + @theme tokens
  router.tsx  main.tsx
```

**Routes stay thin.** A route composes hooks (data) + components (presentation).
Business logic lives in hooks; never fetch inside a presentational component.

## 2. The typed API client (no contract drift)

1. FastAPI exposes OpenAPI at `/openapi.json`.
2. `npm run gen:api` → `openapi-typescript` writes `lib/api/schema.d.ts`.
3. `lib/api/endpoints.ts` wraps each call with those types.

```ts
// endpoints.ts
import type { paths } from "./schema";
export type Item = paths["/api/items/{id}"]["get"]["responses"]["200"]["content"]["application/json"];

export const getItems = (q: ItemQuery) =>
  client.get<ItemList>("/api/items", { params: q });
```

Rule: **never hand-write response types.** Regenerate when the backend changes.
Add `gen:api` to the dev script so it runs against a live uvicorn.

## 3. Data fetching — TanStack Query

All server state goes through Query. No `useEffect`+`fetch`.

**Query keys** are centralized so invalidation is reliable:

```ts
// queryKeys.ts
export const keys = {
  items: (q: ItemQuery) => ["items", q] as const,
  item:  (id: string)   => ["item", id] as const,
  tags:  () => ["tags"] as const,
  sourceTypes: () => ["sourceTypes"] as const,
  insights: (k: string) => ["insights", k] as const,
  tasks: () => ["tasks"] as const,
};
```

Conventions:
- **Lists**: `useQuery(keys.items(q), …)`; `placeholderData: keepPreviousData`
  for paginated/filters so the grid doesn't flash on page change.
- **Detail**: `useQuery(keys.item(id), …)`.
- **Mutations** invalidate the narrowest keys that changed:
  - `PATCH item` → invalidate `keys.item(id)` + `keys.items` (+ `keys.tags`).
  - `ingest`/`resummarize` → on task completion, invalidate `keys.items` and the
    affected `keys.item(id)`.
- **`staleTime`**: ~30s for lists/tags; detail can be longer. Keep it simple.

## 4. Streaming (SSE) — chat tokens & task progress

One helper, two consumers.

```ts
// client.ts
export async function* sse(path: string, init?: RequestInit) {
  const res = await fetch(BASE + path, init);
  const reader = res.body!.getReader();
  const dec = new TextDecoder();
  for (let buf = ""; ; ) {
    const { value, done } = await reader.read();
    if (done) break;
    buf += dec.decode(value, { stream: true });
    // split on \n\n, parse `data:` lines, yield JSON
  }
}
```

- **`useChatStream`** — POST `/api/chat`, append tokens to the in-flight assistant
  message, resolve citations at end. Disable the composer while streaming;
  support abort (new question cancels the old stream).
- **`useTaskProgress(taskId)`** — consume `/api/tasks/{id}/stream`, expose
  `{percent, message, status}`; on `completed`/`failed`, toast + invalidate
  `keys.items`. Used by `TaskRow`.

> Backend: chat already streams via `settings.llm.stream(...)`; the FastAPI
> router re-emits as SSE. Task progress polls `get_task` server-side and pushes.

## 5. Optimistic updates

For instant-feeling edits (tags, title, dismiss):

```ts
useMutation({
  mutationFn: patchItem,
  onMutate: async (next) => {
    await qc.cancelQueries(keys.item(id));
    const prev = qc.getQueryData(keys.item(id));
    qc.setQueryData(keys.item(id), { ...prev, ...next });   // optimistic
    return { prev };
  },
  onError: (_e, _v, ctx) => qc.setQueryData(keys.item(id), ctx!.prev), // rollback
  onSettled: () => qc.invalidateQueries(keys.item(id)),
});
```

Use for: tag add/remove, title rename, inbox dismiss. **Not** for ingest /
re-summarize (those are async tasks → show progress, don't fake the result).

## 6. The required-states contract

Every data-driven surface renders **all four**, or it's not done:

```tsx
if (q.isLoading) return <CardGridSkeleton />;     // matches final layout
if (q.isError)   return <ErrorState onRetry={q.refetch} error={q.error} />;
if (isEmpty)     return <EmptyState action={…} />; // never a dead end
return <Ready data={q.data} />;                    // includes streaming/partial
```

- Skeletons **mirror the final layout** (grid → card skeletons, reader → prose
  blocks). No full-page spinners.
- Errors are **actionable** and, for ingest, show the real backend message.
- Empty states have **one primary action**.

This contract is the operational meaning of "no placeholders".

## 7. The vertical-slice recipe (how to add any feature)

A feature is "done" only when one trip through all of these lands:

1. **Service** exists in `merlin.services` (or add it there — Python).
2. **Router** in `api/routers/*` exposes it; update OpenAPI.
3. `npm run gen:api` → types refresh.
4. **Endpoint fn** in `lib/api/endpoints.ts`.
5. **Hook** in `hooks/` (query/mutation + keys).
6. **Components** (presentational) + the **four states**.
7. **Route** composes hook + components; add to router + sidebar **only now**.
8. Verify in a **real browser** (not just type-checks) — all four states.

Never do step 7 (add nav) before steps 1–6 exist. That's the anti-v2 rule.

## 8. Routing & navigation

- React Router v7. Routes mirror `FRONTEND_V3_SCREENS.md`.
- **URL is the source of truth** for Library filters/sort/page and the open item
  (`/library/:id`) — back/forward and refresh just work; links are shareable.
- Reader is a nested route under Library so "← Library" is real history, not a
  state flag (this is what bit the Streamlit version).
- Add-source and the command palette are global overlays (not routes), but
  add-source may sync a `?add` param so it's deep-linkable.

## 9. Command palette & keyboard

`cmdk`, opened with **⌘K / Ctrl-K**. Sections: Search (items), Go to (routes),
Actions.

| Command | Effect |
|---|---|
| type query | live item search → Enter opens Reader |
| Go to Today / Library / Chat / Inbox / Insights | navigate |
| Add source | open dialog |
| Re-summarize current | (Reader) length submenu |
| Toggle density / Grid·List | Library view prefs |
| Ask: "<query>" | open Chat prefilled |

Global shortcuts (when not in an input):

| Key | Action |
|---|---|
| `/` | focus search / open palette in search mode |
| `g` then `t/l/c/i/n` | go to Today/Library/Chat/Insights/iNbox |
| `j` / `k` | move selection in grids/lists |
| `Enter` | open selected |
| `e` | edit tags (Reader) · `r` re-summarize · `x` delete (confirm) |
| `Esc` | close dialog/palette/reader |

Respect inputs: shortcuts disabled while typing in a field. Document shortcuts in
a `?` help dialog.

## 10. Performance & feel

- **`keepPreviousData`** on lists; debounce search (~250ms).
- Virtualize only if a list grows beyond a few hundred rendered rows (Library is
  paginated, so likely unnecessary at first).
- Lazy-load Tier-2 heavy bits (React Flow graph) via route-level `lazy()`.
- Images: 16:9 container + `object-cover` to crop YouTube `hqdefault` letterbox;
  `loading="lazy"`; show a `--surface-2` placeholder before load.
- Toasts (`sonner`) for async outcomes (ingest done/failed, re-summarize done).

## 11. Quality gates (frontend)

- **TypeScript strict**; ESLint + Prettier; `gen:api` types must be current.
- **Verify in a real browser** for every slice (the Streamlit lesson) — all four
  states, at 1280 and a wide/4K width.
- Optional: Playwright smoke per route (loads, shows ready state) — cheap and
  catches wiring regressions.
- `prefers-reduced-motion` honored; keyboard path works end-to-end.
